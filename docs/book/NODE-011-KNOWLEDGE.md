# NODE 011 — KNOWLEDGE

*The knowing. The eleventh node, and the last organ the Brain element was missing.*

## The empty reply

The founder's own test mail proved the need. His machine received a customer's
question and wrote back: *"We'd be happy to answer your question about our
services."* Polite. Human. And completely empty — it offered to answer, and
answered nothing, because it had nowhere to look.

An agent that talks is not an agent that knows. Nobody pays for polite; they
pay for correct.

## What it is — and what it is not

**Memory** remembers CONVERSATIONS — one drawer per customer, filled as they
talk. **File Upload** is a customer handing over one file for one run.
**Knowledge** is neither: it is the business's LIBRARY — their price list,
their policies, their FAQs — uploaded **once at setup**, the same shelf behind
every answer to every customer forever.

## How it runs

- **Needs:** the customer's question (the text on the wire).
- **Gives:** `knowledge` — the pieces of the library that match.
- Every Brain after it receives those facts automatically, with one
  instruction attached: *answer from these; when the answer is not here, say
  the information is not on hand rather than guessing.* That instruction is
  the whole difference between a library and a liar.
- Found nothing? The log says so — *"the Brain will say so rather than
  invent an answer"* — never a silent shrug.

## Two shelves, honestly separated

- **In the builder** there is no business yet, so the architect types
  *Practice facts* to test with — and every run log says **(sample)**, because
  a sample that keeps quiet about being a sample is a lie.
- **Live**, the node reads the business's real documents through the same
  retrieval the platform's live channels already trusted — search by words and
  their synonyms, whole sections kept, never cut mid-sentence. The practice
  shelf is never read again.

## The business's one job

Upload their documents once at setup — PDF, DOCX, or plain text. The setup
page shows the upload box automatically for any agent that carries this node.
The platform extracts the words, checks the file really is what it claims to
be, slices it into readable sections, and shelves them. Re-uploading the same
file changes nothing; deleting a file empties its shelf.

## The admin's three dials (Admin → Nodes → Knowledge → settings)

1. **Biggest document** (10 MB) — document bytes live in the platform's
   database; every megabyte allowed is database paid for.
2. **Documents per business** (20) — the length of one shelf.
3. **How much one answer may carry** (8,000 characters) — more is not
   smarter; past a point the model drowns and the tokens are pure cost.

Defaults equal what was hard-coded before, so the dials change nothing until
an admin turns one.

## The audit that shaped it

The old developers had built a real knowledge machine — upload, extraction,
chunking, retrieval, 86 passing tests — feeding their receptionist-era
channels. What it never had was a **node**: the workflow engine could not
reach it. Node 011 is their plumbing behind our front door — the same verdict
as the email limb: keep the tested machinery, put our laws in front of it,
and leave their corpse code (an unmounted "v2", a ghost node type) exactly
as dead as we found it.
